# Десктопная версия Review Hub

Дата: 2026-11-04. Статус: этапы 0–6 реализованы; этап 7 запланирован.

## Цель и границы

Один адаптивный сайт для браузера и Telegram Mini App: те же аккаунты, данные,
возможности и API. Десктоп получает удобную компоновку для мыши и клавиатуры.
Мобильный интерфейс сохраняет раздельное нижнее меню: навигация слева,
плавающая кнопка добавления обзора справа.

Выполнены отключение автоматического перехода в Telegram и десктопная оболочка.
Остальные пункты выполняем последовательно, показывая результат каждого этапа.
Этот документ — актуальный план десктопа; существующие `tasks/plan.md` и
`tasks/todo.md` относятся к предыдущей работе и здесь не перезаписываются.

## Что есть в коде

- React 19, TypeScript, React Router, TanStack Query; структура FSD:
  `app → pages → widgets → features → entities → shared`.
- `AppShell` ограничивает приложение шириной 480 px. Нижняя навигация скрывается
  при создании обзора, чтении обзора и просмотре произведения.
- `shared/platform` уже содержит адаптеры Telegram и обычного браузера.
- `AuthGate` разрешает гостевой просмотр публичных экранов; личные маршруты
  открывают `LoginScreen`. Есть браузерный вход через Telegram и по почте.
- `main.tsx` до этапа 0 мог перенаправлять посетителя с десктопа в Telegram
  до монтирования приложения. Публичные маршруты были исключением.
- Публичные экраны поддерживают SSR и гидратацию. Личные данные загружаются
  только в браузере; сервер использует гостевые данные.

## Неизменные технические условия

1. Используем существующие функции `entities/*/api`, `features/*/api` и
   `shared/api/client.ts`: те же URL, методы, payload, парсеры и ошибки.
   Новых desktop-endpoint, отдельного backend и копий бизнес-логики не создаём.
2. Сохраняем существующие маршруты, query-параметры, ключи запросов,
   пагинацию, инвалидирование кэша и проверки доступа.
3. Адаптируем общие страницы и виджеты. Отдельный компонент оправдан для
   десктопной навигации, но не для повторной реализации ленты или редактора.
4. Раскладку переключаем CSS media queries, без определения устройства по
   User-Agent. SSR и первый клиентский рендер должны иметь совместимую разметку.
5. Авторизация, скрытие приватных данных, очистка HTML и обработка 401/429
   остаются прежними. Смена ширины окна не должна повторять запросы,
   сбрасывать фильтры, терять редактор или запускать авторизацию заново.
6. Telegram открывается по явному действию пользователя в сценарии входа.
   Для Mini App сохраняется обмен initData на токен.

## Предлагаемая компоновка

Начальные размеры, уточняемые после проверки на реальном контенте:

| Ширина окна | Компоновка |
| --- | --- |
| До 767 px | Текущий мобильный интерфейс; оболочка до 480 px |
| 768–1023 px | Две колонки: компактная навигация около 80 px и контент |
| От 1024 px | Левое меню 224 px и основная область; общий контейнер до 1280 px |
| От 1280 px | На подходящих экранах возможна правая колонка 256 px |

Отступы между колонками — 24 px; внешние — 24–32 px. Лента и текст обзора
имеют комфортную ширину около 640–720 px, формы — до 800 px.
На широком мониторе контент не растягивается до краёв.
Правая колонка появляется только при наличии полезного содержимого в уже
загруженных данных. Если его нет, остаются две колонки: пустые блоки и новые
запросы ради заполнения пространства не нужны.

### Меню

На десктопе предлагаю вертикальную стеклянную панель слева, закреплённую
при прокрутке. Внутри: логотип, «Главная», «Поиск», «Уведомления» со счётчиком,
«Профиль». Вторичные ссылки — «Достижения», «Магазин», «Настройки».
«Добавить обзор» — отдельная стеклянная кнопка под основной группой,
визуально отделённая от меню, как отдельная кнопка в мобильной версии.

Иконки и подписи белые. Активный пункт отмечается стеклянной подложкой,
плавным перемещением индикатора и `aria-current`; акцент — в тонкой границе.
В компактном режиме остаются иконки с доступными названиями и короткими
видимыми подписями под ними.
Для гостя вход в личный раздел использует существующий `AuthGate`; дополнительные
приватные запросы из меню не запускаются. Само меню не должно исчезать на
десктопной странице обзора, произведения или редактора.

Схема для широкого экрана:

```text
┌────────────────┐  ┌───────────────────────────┐  ┌─────────────────┐
│ Review Hub     │  │ Заголовок / вкладки        │  │ Контекст экрана │
│ Главная        │  │                           │  │ при наличии     │
│ Поиск          │  │ Лента / профиль / обзор    │  │ данных          │
│ Уведомления    │  │                           │  └─────────────────┘
│ Профиль        │  │                           │
│ ────────────── │  │                           │
│ Достижения     │  │                           │
│ Магазин        │  │                           │
│ Настройки      │  └───────────────────────────┘
└────────────────┘
┌────────────────┐
│ + Добавить обзор│
└────────────────┘
```

### Стекло и анимации

Сохраняем прозрачное стекло без плотной тёмной заливки: тонкий светлый край,
небольшой блик и ограниченное размытие. Текст и иконки должны читаться поверх
реального содержимого; если прозрачность мешает, усиливаем локальный контраст,
а не затемняем всё приложение. Текущее CSS-стекло не даёт оптического преломления
Apple Liquid Glass; полноценное преломление — отдельная задача, не обязательное
условие адаптации десктопа.

Анимации — перемещение активного пункта, отклик кнопки на нажатие,
появление диалога. Без постоянных переливов и анимации размытия при прокрутке.
Сохраняем `prefers-reduced-motion`, видимый фокус и контраст в forced-colors.

## Этапы реализации

### 0. Открыть сайт в браузере — выполнено

- Удалить автоматический Telegram-редирект из точки входа и его неиспользуемый модуль.
- Сохранить обычное монтирование и SSR-гидратацию.
- Оставить явный вход через Telegram и почту.

Приёмка: desktop-посетитель остаётся на запрошенном URL; публичные экраны
доступны гостю, личные показывают вход. Проверка: сборка, unit-тесты,
SSR-тесты; отдельно ручная проверка production-сборки без Telegram-сессии.
Отключение редиректа само по себе ещё не расширяет текущую мобильную оболочку.

### 1. Десктопная оболочка и навигация — реализовано

Зависит от этапа 0. Основные места: `AppShell`, новый виджет десктопного меню,
токены раскладки в `app/styles`.

- Добавить адаптивную сетку и левое меню; мобильное меню показывать только
  на узких экранах, не оставляя скрытые ссылки доступными через Tab.
- Согласовать список основных пунктов между двумя меню без зависимости
  одного виджета от другого; общие данные при необходимости разместить в `shared`.
- Сохранить счётчик уведомлений, активные маршруты и обновление данных
  при повторном нажатии. Не создавать второй polling для скрытого меню.
- Снять ограничение 480 px только начиная с планшетной ширины.

Приёмка: на 768/1024/1440 px меню и контент помещаются без горизонтального
скролла; на 320/390 px мобильное меню работает как прежде. Навигация остаётся
на детальных экранах десктопа. Проверка: переходы, прямые URL, Back/Forward,
Tab/Enter, отсутствие повторных запросов из скрытой навигации.

### 2. Лента и поиск — реализовано

Зависит от этапа 1. Основные места: `Feed`, `SearchPage` и их стили.

- Оставить ленту одной читабельной колонкой; адаптировать ширину карточек,
  постеров, строки автора и кнопок.
- Расположить фильтры и сортировку удобнее для мыши, сохранив их состояние.
- Расширить поле поиска и строки результатов; сохранить вкладки,
  задержку поиска и загрузку следующих страниц.

Приёмка: длинные имена и названия не ломают строки, фильтры дают прежние
результаты. Проверка: гость и авторизованный пользователь, пустая выдача,
ошибка API, повтор запроса, пагинация, изменение ширины без сброса состояния.

### 3. Обзор и произведение — реализовано

Зависит от этапа 2. Основные места: `ReviewPage`, `MediaObjectPage`, связанные карточки.

- Произведение: постер и основная информация рядом; обзоры ниже.
- Обзор: ограниченная ширина текста, метаданные и действия рядом с ним;
  стеклянное меню остаётся доступным.
- Сохранить отображение спойлеров, реакции, жалобы и доступные действия владельца.

Приёмка: длинный текст читается без чрезмерно длинных строк; существующие
действия работают с теми же данными. Проверка: прямой SSR-URL, гидратация,
404/503, приватность, клавиатура, длинные заголовки и тело обзора.

### 4. Профиль, подписки, уведомления — реализовано

Зависит от этапа 3. Основные места: `ProfilePage`, `UserHeader`, `NotificationsPage`,
существующий интерфейс запросов на подписку.

- Развернуть шапку профиля по ширине, сохранить текстовые счётчики без обводки.
- Адаптировать коллекцию и вкладки; сохранить различия своего, чужого
  и приватного профиля.
- Подготовить списки подписчиков, подписок, запросов и уведомлений для мыши.

Приёмка: `none`, `pending`, `following`, принятие/отклонение запроса и счётчики
работают как сейчас. Проверка: закрытый профиль, гость, пустые списки,
пагинация и переход из уведомления в запросы.

### 5. Создание и редактирование обзора — реализовано

Зависит от этапа 4. Основные места: `CreateReviewPage`, `ReviewEditor`.

- Увеличить рабочую ширину редактора; отделить сведения о произведении
  от блоков текста и действий публикации.
- Обеспечить удобный toolbar и видимые ошибки; действия не перекрывают поля.
- Сохранить текущие проверки, формат сериализации и API публикации/обновления.

Приёмка: можно создать и изменить обзор; изменение ширины не теряет введённый
текст и фокус. Проверка: ограничения заголовков и блоков, очищаемый HTML,
ошибка отправки, повторный клик, сценарии владельца и гостя.

### 6. Вход, настройки, достижения, магазин и диалоги — реализовано

Зависит от этапа 5. Сначала адаптировать вход; затем остальные экраны
отдельными небольшими изменениями.

- На десктопе форма входа имеет ограниченную ширину и понятный статус;
  Telegram и почта используют существующие сценарии.
- Настройки группируются по смыслу; достижения и магазин получают
  адаптивную сетку без изменения данных и правил доступности действий.
- Диалоги центрируются на десктопе, мобильные панели сохраняют прежнее поведение;
  фокус удерживается внутри и возвращается к инициатору после закрытия.

Приёмка: все существующие возможности доступны на десктопе. Проверка:
успешный/отклонённый/истёкший вход, блокировка popup, неверный email-код,
ошибка API, Escape, Tab, увеличение масштаба до 200%.

### 7. Итоговая проверка

Зависит от этапов 1–6. Новые возможности не добавляются.

- Пройти все маршруты гостем и с действующей сессией.
- Проверить 320, 390, 768, 1024, 1280, 1440 и 1920 px; отдельно высоту окна
  около 600 px, чтобы боковое меню и кнопка создания оставались доступны.
- Проверить Chromium, Firefox, Safari и Telegram Mini App при доступности сред.
- Проверить отсутствие скрытых фокусируемых элементов, наложений,
  горизонтального скролла, скачков гидратации и запросов при простом resize.
- Запустить `npm test`, `npm run build`, `npm run lint`, `npm run test:ssr`.

Приёмка: функциональный паритет с мобильной версией, прежний API,
сохранённые ограничения приватности и работоспособная клавиатурная навигация.
Недоступные для проверки среды явно отмечаются, а не считаются проверенными.
