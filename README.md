# Review App (frontend)

Клиент на React для Telegram Mini App и обычного браузера. Go API — отдельный репозиторий.

Автоматический переход из десктопного браузера в Telegram отключён. Вход через
Telegram открывается по действию пользователя; вход по почте также сохранён.
Поэтапная адаптация интерфейса описана в [плане десктопной версии](tasks/desktop-plan.md).

## Стек

React 19 · TypeScript · Vite · React Router · TanStack Query · Zustand · React Hook Form + Zod · Tiptap · Radix UI

## Архитектура (FSD)

```
app → pages → widgets → features → entities → shared
```

Telegram SDK изолирован в `shared/platform` (адаптеры `telegram` / `web`).

## Запуск

```bash
npm install
cp .env.example .env
npm run dev
```

`VITE_API_BASE_URL` указывает браузеру на Go API. `SSR_API_BASE_URL` — отдельный
фиксированный URL API для Node.js (например, `http://127.0.0.1:8080`). Он
используется только сервером и не зависит от входящих Host/cookies/Authorization.
`npm run dev` запускает SSR-сервер с Vite middleware и HMR.

`npm run build` создаёт `dist/client` и `dist/server`.
`npm start` запускает production SSR на `0.0.0.0:8080`; адрес и порт меняются
через `HOST` и `PORT`. После сборки: `npm run test:ssr` проверяет HTML, метаданные,
HTTP-статусы, изоляцию запросов и защиту данных. `npm test` запускает unit-тесты.

## Страница произведения и приватность

`/media-objects/:mediaId` открывается из поиска и страницы обзора. Информация
загружается через `GET /v1/media-objects/:id`, топ-5 — отдельным запросом
`GET /v1/media-objects/:id/top-reviews`. Метаданные каталога читаются из `info`.
Порядок обзоров определяет API; клиент проверяет размер списка и статус публикации.

В `/settings` доступен переключатель `isProfilePrivate`. У владельца приватного
профиля третья вкладка «Запросы» содержит входящие запросы на подписку
с принятием, отклонением и загрузкой следующих страниц. Кнопки подписки
различают `none`, `pending` и `following`; запрос не увеличивает счётчики подписок.
Уведомление `follow_request` ведёт в `/profile?tab=requests`.

Каталог, поиск, опубликованные обзоры и публичные профили доступны гостям.
Изменения, личные разделы и настройки требуют входа. Недоступный приватный
профиль отображается без его содержимого; подписка доступна через отдельный статус.
Контракты backend описаны в [frontend-api-changes.md](frontend-api-changes.md).

## Форматирование обзоров

Редактор Tiptap сохраняет один HTML-текст `body` до 20 000 Unicode-кодовых точек.
Заголовок необязателен; оценка нужна только для публикации. Поддерживаются разделы
`h3`, цитаты, списки, жирный, курсив и спойлеры `||текст||`. HTML отправляется
без атрибутов; DOMPurify очищает вставку и содержимое перед отображением.
Счётчик декодирует HTML-сущности, исключает теги и переводы строк; превышение
лимита показывает ошибку без обрезания текста. SSR использует jsdom и тот же
санитайзер, что и браузер.

Вход со страницы произведения: `/create?mediaObjectId=<uuid>`. Открытие только
читает `GET /v1/reviews/draft`; первое изменение создаёт черновик через `POST`.
Автосохранение последовательно вызывает `PUT /v1/reviews/:id/draft` с последней
подтверждённой `revision`: debounce 1 с, интервал между запросами минимум 2,5 с.
Публикация — отдельный `POST /v1/reviews/:id/publish` после сохранения всех правок.
При конфликте автосохранение останавливается; свой HTML можно скопировать перед
загрузкой актуальной версии. Текст сохраняется в памяти при ошибках и повторном
входе; закрытие приложения восстанавливает только серверную версию.

Контракт несовместим со старым API: сервер и Mini App нужно выкатывать одновременно.
Полное описание — [frontend-review-editor.md](frontend-review-editor.md).
`npm test` проверяет ревизии, очередь и ограничения; `npm run test:ssr` также
проверяет редактор и клавиатурное раскрытие спойлеров в DOM.

## Комментарии

Под опубликованным обзором доступно обсуждение с ленивой загрузкой веток и страниц.
Визуальный редактор Tiptap сохраняет обычный текст с переносами, без HTML и форматирования;
лимит — 2000 Unicode-кодовых точек после удаления внешних пробелов. Отправка требует входа.
Уведомления `comment` и `comment_reply` открывают и выделяют нужный комментарий,
при необходимости загружая следующие страницы. API-контракт — в `frontend-comments.md`.
`npm test` включает DOM-тесты обсуждения и редактора с подменой сетевых ответов.

## Серверный рендеринг

SSR включён для `/`, `/search` (включая `?q=` и `?tab=`),
`/media-objects/:id`, `/reviews/:id` и `/profiles/:id`. Ответ сразу содержит
содержимое, title, description, canonical и Open Graph; после загрузки JavaScript
React гидратирует его с данными TanStack Query без повторной загрузки страницы.
На каждый HTTP-запрос создаётся отдельный QueryClient; пользовательская сессия
остаётся в браузере. Сохранённые фильтры ленты восстанавливаются после гидратации.

SSR работает только с гостевыми данными. Черновики, закрытые профили и неизвестные
объекты возвращают 404 без содержимого. Личные маршруты остаются клиентскими
и получают `noindex`. Недоступность основного API возвращает 503 с `Retry-After`,
а не пустой успешный ответ; таймаут загрузки данных — 5 секунд.
HTML не кэшируется. Внешние данные экранируются и в метатегах, и в JSON гидратации.

Публичные изображения, включая `/storage`, кэшируются браузером на час.
После истечения срока сервер проверяет `ETag` или `Last-Modified` и возвращает
`304` без содержимого, если файл не менялся. При замене картинки с тем же URL
старая версия может отображаться до часа: для немедленного обновления используйте
новое имя файла. Хэшированные файлы `/assets/` сохраняют годовой immutable-кэш.
Для изображений с внешних доменов действуют заголовки их серверов.

Реализация следует [Vite SSR](https://vite.dev/guide/ssr),
[React hydrateRoot](https://react.dev/reference/react-dom/client/hydrateRoot)
и [TanStack Query SSR](https://tanstack.com/query/latest/docs/framework/react/guides/ssr).

## Sitemap

`/sitemap.xml` — динамический sitemap index. В нём перечислены
`/sitemap-pages.xml` (главная), `/sitemap-reviews-N.xml` и
`/sitemap-authors-N.xml`. Все XML-файлы расположены
в корне сайта, ссылки строятся из ID на фиксированном canonical-домене.

Node.js обходит `GET /v1/sitemap/:entity?limit=1000&cursor=...` до пустого
`nextCursor`. В карты попадают опубликованные обзоры и публичные профили, включая
пользователей без обзоров. Страницы произведений (`/media-objects/:id`) рендерятся
SSR, но исключены из индекса: `noindex` в метатегах и `X-Robots-Tag`, в sitemap
их нет. Опубликованные обзоры приватных авторов
остаются в sitemap; закрытые профили и черновики исключает backend.
`lastmod` не добавляется, поскольку API не возвращает достоверной даты изменения.

XML разбивается по 50 000 URL с проверкой ограничения 50 МБ на файл.
Готовый набор хранится в памяти процесса 5 минут и пересобирается при следующем
обращении. Параллельные запросы используют одну генерацию; набор заменяется только
после полного успешного обхода двух сущностей. Ответы имеют `Cache-Control: no-store`.
При ошибке API просроченный или частичный sitemap не выдаётся: ответ 503 и
`Retry-After: 30`. Если большой обход не завершился за 20 секунд, он продолжается
в фоне, а текущий HTTP-запрос также получает 503. Ошибка генерации ограничивает
следующую попытку паузой 30 секунд. При перезапуске процесса кэш пересобирается.

Контракт описан в [frontend-api-changes.md](frontend-api-changes.md).
Правила разбиения — [Sitemaps protocol](https://www.sitemaps.org/protocol.html).

## Загрузка Telegram Mini App

До подтверждения Telegram-сессии и загрузки профиля показывается загрузочный
экран. Мини-приложение не гидратирует гостевую ленту и не запускает запросы
её компонентов до завершения входа. Скрипт `public/telegram-bootstrap.js`
после Telegram SDK скрывает гостевой SSR-контент до первого рендера React;
`public/auth-loading.css` оформляет начальный и React-лоадер одинаково.
При ошибке входа показывается существующий экран повтора/переоткрытия Mini App.
Гостевой SSR и гидратация обычного браузера сохранены.

### Предпочтения контента

После загрузки собственного профиля с `needsOnboarding: true` приложение предлагает
выбрать 1–32 типа из `GET /v1/review-types`. Выбор сохраняется через
`PUT /v1/content-preferences` и редактируется в настройках. Закрытие опроса без
сохранения не завершает его на сервере. Для работы нужен backend с миграцией
`00028_content_preferences.sql`; поле `needsOnboarding` обязательно в `/v1/profile`.
Предпочтения пока не изменяют ленты: API рекомендаций подключается отдельно.

Тесты контрактов входят в `npm test`, сценарии формы с подменёнными API и базовыми
UI-компонентами — в `npm run test:ssr`.
